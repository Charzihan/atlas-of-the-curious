Pretext, past the hover card

Nine phases that move text layout off the DOM and onto the map, the grid, and the field notes. Ordered so the most visible change ships first and every later phase reuses what came before.

Drafted 10 Sep 2026 Library @chenglou/pretext 0.0.9, vendored Estimates working days, one developer Total about 40 to 54 days
Today

Pretext does one job on the site: it wraps a tagline at 30 characters inside the map hover card. The masonry grid still reads every card's height from the DOM on each filter change, the map draws markers as plain dots with no names, and the dialog renders the story as a single paragraph.

Everything below keeps the site's constraints: strict Content-Security-Policy, no inline styles, no external requests, and a service worker that expects the same file set.

Foundation

One place that prepares text once and answers layout questions cheaply, plus the checks that keep predictions honest. Every later phase calls into it, so it is worth two days before anything visible.

Effort 2 days Depends on nothing Touches js/text.js (new), css/style.css, index.html, js/map.js, scripts/validate-data.mjs, package.json

Text metrics module

A small module that prepares every place's name, tagline, and story in each font role at boot and keeps the prepared handles. It answers "how tall is this text at this width", "which lines does it break into", and "what is the tightest width that keeps the same line count".

The tight-width answer is a binary search over widths, checking the line count at each step, the same approach as pretext's bubbles demo. Its interface is plain data in, plain data out, so in phase 5 the same module runs unchanged inside a worker.

Usesprepare · prepareWithSegments · layout · walkLineRanges · measureLineStats ExposesheightOf(role, id, width) · linesOf(role, id, width) · tightWidth(role, id, maxWidth)

Font role registry

Each text role the site measures gets one canonical entry: family, size, weight, letter-spacing, and line-height. CSS custom properties hold the values; the module reads them once from computed style, so CSS stays the single source of truth.

Roles to register: card name, card tagline, dialog story, dialog quote, map label, ocean label, hover card, notebook. Replace the generic ui-monospace keyword with a named monospace face in both places, because a generic keyword can resolve to a different font in canvas than in CSS.

Agreement check in development

On localhost only, compare the predicted height of five cards against the DOM's measured height and warn in the console when they differ by more than a line. Font drift between CSS and the registry shows up here before it ships.

Automated overflow checks

A headless-browser test, run by the validate script, prepares every name, tagline, and chip label at 320, 768, and 1280 pixels and fails when a name needs more than two lines in a card, a chip breaks across lines, or a hover card passes three lines. A bad dataset entry is caught before it ships, without anyone opening the site.

This is the development-time verification the pretext README describes. Playwright joins the dev dependencies; the test takes a few seconds for 40 places.

Useslayout · measureLineStats
Done when
  • The map hover card wraps through the module instead of its own probe canvas.
  • The agreement check passes in Chrome, Firefox, and Safari.
  • The overflow test runs with pnpm validate and passes for the current 40 places.
  • The service worker's file list includes the new module.
1

Labels on the map

The Text Atlas is the site's signature, and it is mute. Names set into open water, appearing as you zoom, turn a diagram of dots into a map you can read.

Effort 5–6 days Depends on phase 0 Touches js/map.js, css/style.css

Coastline-aware labels

Each marker's name is placed into sea cells only. The layout tries eight anchor directions around the dot; for each candidate it reads the run of free water cells per row from the land grid and feeds those widths, one row at a time, to pretext's variable-width line routine. A label is scored by line count, distance from the dot, and overlap with an occupancy mask of cells other labels already use. The best candidate wins.

This is the obstacle-routing pattern from pretext's dynamic-layout demo, with continents as the obstacles. The occupancy mask is a byte array the size of the grid, cleared on each rebuild.

UseslayoutNextLineRange · materializeLineRange · measureLineStats Renderspositioned spans in the marker layer, so labels stay hoverable and readable by assistive tech

Zoom-level typography

Three tiers keyed to the zoom factor: nothing at the base view, the name from about 1.4×, name and tagline from about 2.4×. Each name is prepared once; only the cheap layout step runs on zoom frames, so the labels re-flow live inside the existing animation loop.

The available width in characters changes with zoom, which is exactly the case pretext's separation of prepare and layout is built for.

UseslayoutWithLines on the tier's prepared handle Mobilelabels off below 640px; the hover card carries the name instead

Ocean names in spaced capitals

PACIFIC OCEAN, INDIAN OCEAN, and the named seas set in letter-spaced capitals across open water, the convention printed atlases use. Letter-spacing is an input to pretext's prepare step, so each label's width is exact before placement, and ocean names share the occupancy mask with the place labels so the two never collide.

A short list of ocean and sea names with anchor coordinates lives in the map module. Tracking widens slightly with zoom, and the width stays known at every step.

UsesprepareWithSegments with letterSpacing · measureNaturalWidth

Hover card that hugs its text

The card currently wraps at a fixed 30 characters and often leaves one word on the last line. Ask the metrics module for the tightest width that keeps the line count, size the card to the widest line plus padding, and measure before deciding which side of the marker the card opens on.

UsestightWidth from phase 0
Done when
  • No label cell overlaps land, another place label, or an ocean name at any zoom. A dev assertion walks the occupancy mask against the land mask after every rebuild.
  • None of the 40 taglines shows a one-word last line in the hover card.
  • Zooming with labels visible stays at frame rate on the laptop that runs the ripple sim today.

The predictive grid

Card heights become arithmetic instead of measurement. That removes forty forced layouts per filter change and unlocks transitions the current code cannot do: cards that move to their new slot, and a card that opens in place.

Effort 4–5 days Depends on phase 0 Touches js/app.js, css/style.css

Predictive masonry

A card's height is fixed chrome plus name lines times line-height plus tagline lines times line-height, all from prepared handles. The masonry pass becomes writes only: set width, left, top, and the grid's height, with no reads in between.

This is pretext's masonry demo applied to the existing shortest-column layout in layoutMasonry. The pooled card elements stay as they are.

UsesheightOf("card-name") · heightOf("card-tagline") Removesthe per-card offsetHeight read

Cards that glide on filter

Because the new positions are known before the DOM changes, each card can animate from its old slot to its new one with a transform. Cards leaving the filter fade in place; cards entering rise into their slot. Reduced-motion turns it into a plain swap.

Techniquerecord old position, apply new, invert with a transform, play to identity

The card under your cursor stays put

When a filter reflows the grid, the card under the pointer, or the one holding keyboard focus, keeps its place on screen. The page scroll is adjusted by the difference between that card's old and new top before the frame paints. Positions are known before render, so there is nothing to measure and no flash.

Usesthe predicted tops from the masonry pass

Balanced taglines, fitted names, a fitted headline

Each tagline gets a max-width equal to its tight width, so the last line carries its share of words. Long names such as the Vatnajökull ice caves step down in font size until they fit one line, with a floor, and otherwise take two lines cleanly. The hero headline is fitted the same way at every viewport width, so it always lands on two lines with whole words, the technique pretext's dynamic-layout demo uses for its title.

UsestightWidth · measureNaturalWidth · measureLineStats at candidate sizes

Expand a card in place

On desktop, a card can open in the grid instead of the modal. Its expanded height is known from the story's prepared handle at the card's width, so the card grows and its neighbours slide down at the same time, with no measurement and no second reflow. The modal stays for phones and for deep links.

This is pretext's accordion demo inside a masonry. The expanded card keeps the plain paragraph; the editorial treatment in phase 3 is for the modal.

UsesheightOf("story", id, cardWidth)
Done when
  • The Performance panel shows zero forced synchronous layouts during a filter change or a card expansion.
  • Predicted card tops match rendered tops within one pixel for all 40 cards in the dev check.
  • The hovered card stays under the cursor after a filter change, and switching categories animates rather than reflows.
3

The editorial field note

The stories are the best writing on the site and they are shown as a grey paragraph in a modal. Manual line layout lets the dialog read like a printed spread without giving up the strict CSP.

Effort 6–8 days Depends on phases 0 and 2 Touches js/dialog.js (new, split from app.js), css/style.css, js/data.js

The story as a spread

Three devices from print. A drop cap: the first grapheme set large, with the first few lines laid out at a narrower width to route around it. A pulled quote: the field note sits in a box partway down, and body lines beside it shrink to flow around. Two columns from 900px: the left column consumes lines until it is full, and the right column resumes from the same cursor, so the story is one continuous stream.

Lines render as absolutely positioned spans built with DOM APIs, which the CSP allows. The original paragraph stays in the DOM, visually hidden, so screen readers and find-in-page still see one paragraph.

UseslayoutNextLine with a per-line width · walkLineRanges to size the columns

Justified columns, with rivers watched

On wide screens the two columns are justified. Pretext's justification demo carries a model that finds the best set of line breaks for a whole paragraph, the Knuth-Plass approach, and flags rivers, the white channels that run down justified text. The dialog tries three column widths and keeps the one with the fewest rivers. Ragged-right stays the default on narrow screens.

The model is userland code built on pretext's per-segment widths, so it ports as a module of its own. Soft hyphens from the feature below feed it extra break points.

Usesper-segment widths from prepareWithSegments · walkLineRanges

Smooth previous and next

The incoming story's height is computed before it renders, and the dialog animates from the current height to the new one while the content swaps at the midpoint. Today the dialog jumps between a short story and a long one.

UsesheightOf("story") at the dialog's inner width

Lines that arrive one at a time

Since the line breaks are known up front, the container is set to its final height first and lines fade in with a short stagger. It reads as the field note being written, and nothing below it moves. Reduced-motion shows everything at once.

Soft hyphens for long names

A small dictionary of break points for the names that misbehave in narrow columns: Białowieża, Zhangjiajie, Jökulsárlón, Sossusvlei. Soft hyphens are inserted at render time, never stored in the dataset, so search keeps matching. Pretext shows the hyphen only when the break is taken.

Metadata as inline chips

"Best time to visit" and "Nearest major city" become rich inline flows where months and distances are chips that never break in the middle but still wrap with the sentence around them.

UsesprepareRichInline with break: "never" and extraWidth for chip padding
Done when
  • All 40 stories render without overflow at 360px, 768px, and 1280px.
  • Justified columns show no river longer than three lines in any of the 40 stories at 1280px.
  • Keyboard previous and next animate the height; Escape still closes.
  • A screen reader reads the story as one paragraph, and browser find-in-page still finds words in it.

Names in their own script

An atlas that only speaks Latin script is missing half of each name. Pretext handles Arabic, Thai, CJK, and mixed-direction wrapping, which makes this cheap to add and honest to the subject.

Effort 2–3 days Depends on phase 1 for map display Touches js/data.js, scripts/validate-data.mjs, scripts/build-place-pages.mjs, js/app.js, js/map.js

A native-name field

Every place gains a name in its local script and a language tag: 張家界 for Zhangjiajie, البتراء for Petra, Jökulsárlón as written in Iceland. The validator requires it, and the generated share pages print it under the title.

Shown wherever the name is

The hover card and the dialog show the native name under the Latin one. The third map label tier shows both. Direction comes from pretext's per-segment bidi levels, so a right-to-left name gets the right dir and wraps correctly next to Latin text.

UsesprepareWithSegments and its segLevels

Search matches, highlighted

Matched search tokens in card taglines render as bolder fragments through the rich inline helper, so the wrap stays correct even though bold glyphs are wider.

UsesprepareRichInline with two font strings

Ready for native-language blurbs

The language tag sets pretext's segmentation locale per place, Korean and Chinese text uses keep-all breaking, and Japanese text relies on the line-start and line-end prohibitions pretext already implements. Nothing changes on screen yet; it means a future native-language tagline wraps correctly the day it is added, including Thai, which has no spaces between words.

UsessetLocale · wordBreak: "keep-all" · built-in kinsoku rules
Done when
  • 40 of 40 places have a native name, and the build fails if one is missing.
  • Arabic, Thai, and CJK names wrap inside the hover card without breaking mid-word.
  • A test fixture with a Japanese and a Thai tagline breaks at correct boundaries in all three browsers.
  • Highlighted taglines have the same line count as unhighlighted ones for every query in a short fixture list.
5

The living sea

The showpiece. Every earlier phase makes text cheap to re-lay; this one spends that budget on the ocean, where the ripple simulation already lives, and moves the layout work off the main thread so the ripples never wait.

Effort 8–11 days Depends on phases 1 and 4 Touches js/map.js, js/text-worker.js (new), css/style.css, sw.js

Layout off the main thread

The metrics module from phase 0 is loaded a second time inside a Web Worker. Pretext measures through OffscreenCanvas and segments through Intl.Segmenter, both available in workers, so label placement and idle-mode layout run there and post cell positions back as typed arrays. The ripple loop on the main thread never blocks on text.

The worker is a same-origin module, which the CSP already allows. Fonts must be loaded in the worker too; the registry from phase 0 ships the same font strings to both sides.

Usesthe phase 0 module unchanged · postMessage with transferable buffers

Stories on the water

On hover, the tagline spills into the sea cells around the marker, routed around land row by row, and is drawn into the sea layer so the ripples displace the glyphs. Open the place and the first sentences of the story follow.

Usesthe phase 1 routing, with the sea canvas as the target instead of spans

Sea of stories, when idle

After twelve seconds without pointer movement, sentences from random field notes drift along ocean rows as slow currents, each row's usable width bounded by the coastlines on either side. Any pointer movement dissolves them. Off under reduced-motion and on phones.

Each sentence is prepared once and re-laid every frame as its row's free width changes with its position. That per-frame layout is the case pretext exists for; the DOM never measures anything.

UseslayoutNextLineRange per row per frame, in the worker

Drifting words you can click

Each drifting sentence keeps its per-segment widths, so a pointer position maps to a line and then to a word. Hovering a sentence brightens it, and clicking it opens the place it came from. Because every word has its own position, a ripple can also nudge words individually rather than shifting a whole line.

Hit-testing on canvas text without any DOM, using the same segment widths that placed the words.

Usessegments and widths on the prepared handle · materializeLineRange
Done when
  • Idle mode holds frame rate with DevTools CPU throttling at 4× on a mid-range laptop, and no layout call runs on the main thread while it plays.
  • No glyph is ever drawn on a land cell in either text feature; the dev assertion from phase 1 covers this too.
  • Clicking a drifting sentence opens the right place in a test of twenty random picks.

Ways to read

Two features for people who come to read rather than browse. Both rest on the same idea: when the height of any text is known in advance, pages and text boxes can be honest about their size.

Effort 4–6 days Depends on phases 2 and 3 Touches js/reader.js (new), js/app.js, css/style.css, index.html, sw.js

A paginated field guide

A book mode that lays all 40 field notes into pages of a fixed height, in the current filter's order. The layout consumes lines through the cursor until a page is full and continues on the next, so the page count is exact the moment the mode opens and "page 12 of 37" is true. Arrow keys turn pages, a place's page is deep-linkable, and a print stylesheet uses the same page geometry so what prints matches what is on screen.

Pagination is the multi-column flow from phase 3 with pages instead of columns. Widows and orphans are avoided by looking one line ahead before closing a page.

UseslayoutNextLineRange · materializeLineRange · heightOf for the headings

A visitor's notebook

Each place gets a notes box for the visitor's own thoughts, saved in local storage and never sent anywhere. The box grows with the text from a predicted height, so typing never causes a reflow, and a "copy as postcard" button exports the note with the visitor's line breaks intact.

Pretext's pre-wrap mode keeps tabs and hard breaks, which is what a textarea needs. Notes never enter the URL or the generated share pages.

Usesprepare with whiteSpace: "pre-wrap" · layout
Done when
  • The page count is correct for every window height from 600 to 1200 pixels, checked against a DOM-measured render in the dev build.
  • Printing the field guide produces the same page breaks as the screen.
  • Notes survive a reload, are absent from the URL and share pages, and typing into one triggers no forced layout in the Performance panel.

Shapes and paths

Text set into a shape only this atlas has. The land grid knows which country each cell belongs to, and a route between two places is a line like any other, so both become widths fed to the same variable-width layout used since phase 1.

Effort 5–7 days Depends on phases 1 and 5 Touches scripts/build-map.mjs, js/landmap.js, js/map.js, js/dialog.js

A story in the shape of its country

Open a place and its story fills the silhouette of its country on the map. Per row, the run of that country's cells becomes the line width, and the story flows into the shape from the top row down, with a minimum run so a one-cell sliver never holds a word. Bolivia's outline filled with the story of Salar de Uyuni; Jordan's with Wadi Rum.

The build script adds a country index per cell to the land grid. The palette already encodes a country hue, so this is a small change to the generator and a rebuild of the grid file. Small countries and islands, Rapa Nui or Komodo, fall back to a bounding region around the marker.

UseslayoutNextLineRange with a width per row · materializeLineRange

A field note along the route

After Locate me, the great-circle path to the nearest wonder is drawn and cut into short segments. Each segment's length becomes a line width, and the field note reads along the journey, each run of glyphs rotated to its segment's heading. The dialog offers the same between any two places.

Variable width per line is the same call as the coastline routing; the only new work is the rotation when drawing.

UseslayoutNextLineRange · canvas rotation per segment
Done when
  • Every one of the 40 stories fits its country's silhouette at the desktop grid size, or falls back cleanly where the country is too small.
  • Route text never crosses a place label or an ocean name.
  • Both features render in one frame from the worker's output.

A serif atlas

The map is a monospace grid because that is what makes ASCII art easy. Pretext knows the width of every glyph in a proportional face, which removes the reason to stay monospace.

Effort 4–6 days Depends on phase 5 Touches js/map.js, css/style.css, index.html (mode toggle)

A serif map mode

A toggle in the map controls redraws the coastlines in the site's Georgia face. The glyph palette is scored by both brightness and how close each glyph's measured advance is to the target cell, so the continents keep their shape in a proportional font.

This is pretext's variable-typographic-ascii demo applied to the land mask. Markers keep their grid positions in both modes.

UsesprepareWithSegments for its per-segment widths

The sea as a typographic fluid

In serif mode the ripple field renders the way the community fluid-smoke demo renders smoke: each cell picks a glyph by both brightness and measured advance, so crests and troughs read as tone rather than as a fixed set of ocean glyphs. Same simulation, different ink.

Usesthe serif glyph palette from the feature above, sampled per cell per frame
Done when
  • Toggling serif mode leaves every marker at the same pixel and the land mask unchanged.
  • The fluid rendering holds frame rate under the same throttle as idle mode.

Guardrails for every phase

  • Font strings mirror CSS exactly. Family, size, weight, and letter-spacing at prepare time; line-height at layout time. The phase 0 registry is the only place these live, and the worker receives the same strings.
  • Prepare once, lay out often. Preparing inside a frame loop throws away the precomputation that makes layout cheap.
  • Predictions match the browser because pretext mirrors each engine's line-breaking quirks for Safari, Chromium, and Gecko. Re-run the agreement and overflow checks whenever the vendored version is bumped.
  • The CSP does not loosen. DOM APIs and CSSOM only, no inline style attributes, canvas and the worker stay same-origin.
  • Reduced-motion is respected by the reveal, the gliding cards, idle mode, and the fluid sea.
  • Each phase ships behind a flag in the metrics module so a regression can be switched off without a revert.
  • The service worker's file list is updated whenever a file is added, or the offline cache silently misses it.

Deliberately later

  • Per-place share images with wrapped titles. Pretext has no Node path yet, so this needs a headless browser step in the build. The overflow test from phase 0 sets that step up, which makes this cheaper afterwards.
  • Grid virtualization. Phase 2 makes it possible, but 40 cards do not need it. Revisit past about 200 places.
  • A translated interface. Native names are one field; a full second language is a different project.
